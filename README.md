## 1. Project Overview
This project demonstrates the deployment of Wazuh Manager and Agent, the detection of attacks, and the analysis of alerts generated by my own attack. The main purpose of this project is to learn how a SIEM tool like Wazuh works to detect attacks and how it displays alerts on its dashboard through hands-on lab practice.This was my first time working with a SIEM. At first, I found it difficult to understand how alerts are generated, but after performing the attack myself, I understood the complete flow

## Key Objectives:
- Deploy Wazuh Manager on VirtualBox
- Connect Wazuh Agent to the Manager
- Detect a SSH Brute-Force Attack
- Analyze alerts from generated logs
- Block the attacker (Kali) IP address

## Lab Components Detailed Explanation

**1. Attacker - Kali Linux:**
- **Role:** Hacker
- **IP Address:** `10.0.2.15`
- **Action:** Used Hydra to perform an SSH Brute Force attack on the Ubuntu Server.

**2. Victim - Ubuntu with Wazuh Agent:**
- **Role:** Target System being monitored
- **IP Address:** `10.0.2.3`
- **Action:** Wazuh Agent is installed here. When an attack happens, the agent does not block it; it only reports it to the Manager.

**3. Defender - Wazuh Manager:**
- **Role:** SIEM Server
- **IP Address:** `10.0.2.4`
- **Action:** Receives logs from the Agent and analyzes them using detection rules.

**4. Analyst - Wazuh Dashboard:**
- **Role:** Security Analyst View
- **Access:** Via browser at `https://10.0.2.4`
- **Action:** Analyst can view alerts, severity, and attacker IP address.

## Network Configuration
- All VMs are on **NAT Network** in VirtualBox
- Network Range: `10.0.2.0/24`

## Attack

From Kali Linux, Hydra attempts a list of passwords against the `analyst` SSH account on the Ubuntu Server:

'hydra -l osboxes -P /usr/share/wordlists/rockyou.txt -t 4 -v -f ssh'

# Detection

| Rule ID | Level | Description |
| ------- | ----- | ----------- |
| 5760 | 5 | sshd: authentication failed |
| 40111 | 10 | Multiple Authentication Failure |
| 5503 | 5 | PAM: user login failed |
| 2501 | 5 | syslog: User authentication failure |
| 5758 | 8 | Maximum authentication attempt exceeded |



## Challenges Faced
- Initially, Wazuh Manager was not starting because of low RAM, so I increased it to 4GB.
- The OVA file was corrupted during import, so I had to re-download it.
- Agent was not connecting due to NAT network issue, fixed by checking port 1514.

## 4. Evidence & Logs

All generated logs are available in the `logs/` folder for verification.

| File | Description |
| :--- | :--- |
| `logs/alerts.json` | Main alert file in JSON format (2.5 MB). Contains all alerts with Rule ID, attacker IP, and timestamp. |
| `logs/alerts.log` | Same alerts in plain text format, human-readable. |
| `config/ossec.conf` | Wazuh Manager configuration file. |

# How to Analyze Logs:

### Count total alerts
cat alerts.json | wc -l

### Check brute force alerts - Rule 5712
cat alerts.json | grep "5712"
